# 家庭室内导航可靠性冲刺

日期：2026-10-07  
状态：已加入“陪同实验导航”真人测试入口；只允许短距离、熟悉平坦区域的陪同测试，不可作为独立安全导航。

## 目标

把现有“家庭扫描 + 位置匹配 + 语音路线”收敛为一条可测闭环：可信家庭定位 → 用户确认的地点与通道 → 路线规划 → 当前帧避障 → 到达或安全停止。第一条试验路线限制在同一楼层的两个房间和一段走廊。模型外观不作为导航正确性的依据。

## 现状和根因

- 手机用 ARCore 位姿维持单次会话内的相对运动，家庭后端返回初次会话到父模型的对齐；目前导航运行时没有周期性视觉重定位纠偏，因此持续走动仍会积累漂移。
- 家庭地图保存的是占据/自由证据和用户标记点；标记点不是用户脚下的实时位置，也不包含已确认门洞连接图。
- `HomeRoutePlanner` 在持久 2D 地面投影上生成候选路径。它不能验证实际脚下支撑、人体净空、门洞当前状态或楼梯，因此不可将其结果解释为安全证明。
- 语音路径曾允许以用户口述房间作为定位替代，并从房间锚点输出方向；这与自动定位要求冲突，第一轮关闭该回退。
- 实时障碍此前主要按障碍与当前人的距离判断，没有检查动态占据是否落在接下来的路线走廊上；障碍提示后仍可能保留旧路线状态。

## 第一轮实施

1. **定位门控**：生产入口只接受电脑返回的家庭地图坐标与朝向；口述房间名只作地点语义，不作为位姿。定位或 ARCore 跟踪失效时撤销导航，不发方向指令。
2. **路线障碍急停**：把当前非膨胀占据样本变换到家庭地图坐标，投影到路线前方短走廊。若未来 1.8 米内路线走廊被占据，取消当前导航并要求停下确认；第一轮不自动承诺绕行。
3. **路线语义限制**：持久栅格路线只称“候选路线”；缺少已确认通道/楼梯/净空证据时不显示“安全路线”。未知区域不能被当作可通行区域。
4. **自动验证**：覆盖未定位时禁止起步、前方路线被挡即急停、路线外障碍不误停、跟踪/实时深度过期即停。
5. **导航图就绪门控**：普通扫描地图不等于可走地图；只有后端验证图可用、且手机规划器实际消费该图时才可进入路线规划。手机目前仍使用旧 2D 扫描栅格，所以即使后端将来返回 ready 也不会误开放。扫描结束状态明确显示“导航图待验证”。
6. **受控真人测试入口**：用户先确认有陪同人员，再依次进行家庭地理位置确认和家庭视觉定位；只有当前仍有家庭定位的实时位姿时，才开放最多 5 米的旧 2D 候选路线。屏幕和语音明确声明“陪同实验路线、未安全认证”。退出、定位失败、相机/深度启动失败都会撤销实验模式。

## 后续工作（本轮不假装已完成）

- 周期性重定位：用家庭关键帧/局部特征多帧定位纠正 ARCore 漂移；若纯视觉在住宅失败率高，再评估少量 AprilTag 或 BLE 辅助点位。
- 建立用户确认的房间—门洞—走廊拓扑图；每条边记录实际通过验证、宽度、楼层/高度变化、地图修订和复核时间。未验证的边不参与路线。
- 局部避障由“急停”升级为仅在当前已观测且有连续支撑的区域内生成绕行，并验证重新接回全局路线。
- 脚下支撑、头部净空、落差、楼梯和多层连接尚未通过真机专项验收前，一律拒绝自动引导通过。
- 家庭路线需要有人陪同测试；所有错误房间接受、错转、障碍漏报、停止延迟和定位恢复都要记录。

## 通过标准

自动测试只证明逻辑门控，不证明现实安全。受控试验至少覆盖两个房间往返、定位丢失、临时障碍挡路、障碍在路线外、门关闭、手机朝向变化和 ARCore 重定位跳变；正式验收沿用 `HOME_NAVIGATION_PLAN.md` 的 M3/H3/H4/H5 指标，失败时保持停止态。

## 陪同真人测试步骤

1. 确认两台电脑后端正常、手机可连接；只选熟悉的同一楼层平地，起点到终点不超过 5 米，路线无楼梯、台阶和门槛。陪同者全程在用户身边并负责阻止用户进入障碍物。
2. 确认模型至少有两个由用户标记的地点。点“陪同实验导航”，在系统对话框确认陪同者在场；观察地理位置确认结果，再等待家庭视觉定位完成。定位失败、后端未连接或深度未就绪时不开始走。
3. 定位成功后按语音说目的地。手机应先声明“陪同实验候选路线、未安全认证”，随后给出方向和距离；若没有实时定位或地图不连通，应拒绝路线。
4. 第一趟只按 1—2 步短促移动，每条语音后停下由陪同者核实方向。不要闭眼独立试走，不用身体碰撞来验证避障。
5. 静止时让陪同者把软质轻物放在前方路线内，用户不要继续走。手机应停止旧路线并播报停下；拿开物体后也不得自动恢复旧路线，应重新定位/发起导航。
6. 测偏航、失去跟踪、遮挡相机或切后台等情况时都保持静止操作；预期是旧指令失效并要求停止/重新定位。任何一次仍播旧方向、未停或位置明显错误，都立即结束测试并保留日志。

### 第一轮结果与限制

- 本轮将“语音说自己在卧室”从定位证据中移除，避免以房间标记点冒充脚下位置。
- 实时占据证据只有在路线前方短走廊、近身范围或明显偏离路线时才撤销路线；不会自动给绕行方向，用户需停下确认。
- 当前全局路线仍来自持久 2D 投影，不是用户确认的房间/门洞拓扑图；本轮没有验证实际地面支撑/头部净空，也没有解决首次定位后的长期漂移。
- 当前后端将导航图固定标为 `safeForNavigation=false` / `navigationReady=false`；而手机也尚未消费该 3D 图进行路线规划。因此新逻辑会拒绝路线导航。这是预期的安全门控；重新开放前必须完成通行图接入、规划器迁移和现场验收。
- 真人测试只能通过显式选择“陪同实验导航”临时使用候选路线；必须在熟悉、平坦、空旷的短距离区域，由陪同者全程监护。禁止独自跟随语音行走，也不要用楼梯、台阶或门槛测试。
- 因此 APK 是逻辑闭环实验版，不代表已达到室内导航或可独立安全行走程度。
