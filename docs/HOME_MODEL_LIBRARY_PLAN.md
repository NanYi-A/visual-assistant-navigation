# 家庭模型库与认知模型实施方案

> 本文负责模型库和后端产物。家庭识别、用户口述房间标注、跨会话定位、语音目的地和动态绕障的权威规范见 `HOME_NAVIGATION_PLAN.md` 2.0；两者冲突时以后者为准。

## 1. 产品目标

用户点击“采集家庭路线”时立即新建一个独立家庭模型空间。扫描过程中实时展示便于家人理解的彩色表面；电脑同时积累可验证的三维占据证据。结束扫描后，电脑在后台生成能回答“哪里能走、哪里不能走”的认知模型，并把扫描模型与认知模型作为同一条模型记录展示。

彩色表面只用于查看；急停、碰撞和路径规划只读取认知模型。任何算法补全不得进入安全导航层。

## 2. 一个模型空间的文件结构

```text
models/<model-id>/
  manifest.json              # 名称、时间、阶段、进度、版本和错误
  scan/colored_mesh.ply      # 用户扫描得到的彩色表面
  scan/coverage.json         # 已扫/缺口范围与轨迹
  cognition/occupancy.vamap  # 空闲、占据、未知、冲突证据
  cognition/collision.ply    # 供家人查看的碰撞体积
  cognition/navigation.json  # 可站立表面、连接、净高、宽度和安全余量
  cognition/preview.ply      # 绿色可走、红色不可走、灰色未知的认知预览
  semantics/places.json      # 用户口述并确认的房间/地点、同义词、区域和到达区
  localization/keyframes.json # 家庭识别和六自由度重定位关键帧索引
```

`model-id` 在手机点击采集时生成，彩色和导航两条通道必须携带同一个 ID。不同模型不得共享 ARCore 原点或地图文件。

## 3. 状态机

1. `SCANNING`：彩色模型实时出现；占据证据实时融合。
2. `UPLOADED`：用户结束扫描，后端冻结输入版本。
3. `PROCESSING`：去除小碎片，提取碰撞体积、地面/坡面/楼梯候选、门洞和三维连接。
4. `READY`：扫描模型与认知模型均可查看；导航只使用该版本。
5. `NEEDS_RESCAN`：覆盖不足或冲突过多，展示具体补扫位置。
6. `FAILED`：保留扫描模型、错误原因和重新处理入口。

## 4. 认知模型算法

- 输入：ARCore 位姿、Raw Depth、置信度、相机内参和可选 YOLO 标签。
- 占据层：沿相机射线写入空闲证据，深度终点写入占据证据；保留未知与冲突，不猜测遮挡区域。
- 碰撞体积：三维体素去孤立小块，按人体宽度和定位误差做 3D 安全膨胀。
- 可站立表面：从三维表面法向、高度连续性、坡度、净高和最小宽度判断；楼梯保存为逐级连接，不能投影成单层 2.5D 地图。
- 导航图：在可站立表面生成节点和边，边记录宽度、坡度、台阶高度、头部净空与可信度。
- 语义层：YOLO 只给障碍命名，不决定几何是否可通行。
- 房间语义层：房间名只接受用户在稳定定位位置的口述和二次确认；视觉模型不得自动命名房间。

## 5. 时间预算

- 首个彩色模型：获得可靠深度后 15 秒内。
- 增量碰撞/空闲更新：帧到结果 3 秒内。
- 结束扫描后的最终认知处理不设固定时长上限；整屋规模随面积和关键帧数量增长，必须显示真实阶段、最近进度时间和错误原因。
- 只有进程明确失败、输入损坏或用户主动取消时才标记 `FAILED`；长时间运行本身不是失败。处理中持续写心跳，应用和后端重启后从已落盘检查点恢复或重新执行可重复阶段。

## 6. 手机模型库

- 家庭扫描入口首先创建记录，默认名称为“家庭模型 + 日期时间”，可重命名。
- 模型卡显示缩略图、扫描时间、处理状态、覆盖率、冲突数和后端最后更新时间。
- 模型详情提供两个明确视图：
  - “真实扫描”：彩色表面、轨迹、缺口；
  - “通行认知”：绿色可走、红色碰撞、灰色未知、当前位置和规划路线。
- `PROCESSING` 显示真实阶段和剩余时间估计；网络断开显示“等待电脑”，不能显示笼统的“模型尚未形成”。
- 删除模型需要同时删除手机索引和电脑对应目录；本阶段不自动复用或合并旧模型。

## 7. 验收条件

- 连续创建两个模型时，文件、session、revision 和界面完全隔离。
- 杀死手机进程、重启应用后，模型库记录仍存在，能继续查看已完成模型。
- 杀死任一后端后，守护进程恢复；模型状态从“等待电脑”继续，不产生第二个重复模型。
- 扫描结束后持续显示处理阶段和最近进度；处理完成进入 `READY`，证据不足进入 `NEEDS_RESCAN`，明确错误才进入 `FAILED`。
- 在包含门、桌椅、墙和楼梯的场景中，认知视图正确区分可走、碰撞和未知；楼梯不再消失于单层投影。
- 家人能在真实扫描视图指出主要墙面/家具；视障用户获得的路线只经过认知模型确认的连通可走区域。

## 9. 中断续扫与安全合并

- [x] 进程被系统杀死后保留已经落盘的主模型，不尝试恢复失效的 ARCore 世界坐标。
- [x] 用户从模型库点击“继续补扫”时创建独立分段；手机和两个电脑后端共享新的分段 ID，并记录主模型 ID。
- [x] 分段初始状态固定为 `WAITING_RELOCALIZATION`、`mergeAllowed:false`；此时可以查看和继续采集，但不得参与主模型路径规划。
- [x] 使用主模型与分段的重叠 RGB-D 关键帧估计刚体变换；至少两组独立父/子帧支持同一变换，并通过深度表面重叠检查。第一批真实数据已区分可对齐分段与证据不足分段。
- [x] 对齐不充分时返回 `NEEDS_OVERLAP_RESCAN`；不能以最近位姿或手工平移猜测坐标。手机端语音引导与状态同步仍待下一阶段接入。
- [x] 对齐通过后保留原始主模型与分段文件，另生成可回滚的合并版本；用户地点标记随刚体变换进入合并坐标系。合并版本同时保存父/子变换后的关键帧，后续补扫重定位优先使用当前活动版本。
- [x] 真实分段 `58999814161086` 与父模型 `57102012097175` 已生成 `merge_58999814161086`：父 30,779 面、子 29,338 面，清理后 60,117 面；父 11 帧与子 8 帧进入统一坐标系，两个用户地点保留。该候选仍标记 `safeForNavigation=false`，占据/净空认知等待重建。
