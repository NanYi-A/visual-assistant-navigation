# 语义与深度对象融合改造方案

## 问题

当前空间页已经从同一 ARCore 帧取得 YOLO 检测、Raw Depth 和位姿，但危险播报仍有两条入口：深度表面回调可以播报“物体表面”，YOLO 回调又会把二维检测类别与空间地图中最近的任意表面距离拼接。多个物体同时出现时，类别、方向和距离可能不属于同一个目标；两个异步入口还会争用同一冷却时间。

## 本轮目标

1. 建立明确的三维语义对象结构，保留类别、置信度、三维位置、深度支持数、深度离散度、来源帧和时间；
2. 检测框与深度匹配从 Renderer 中拆成可单元测试的纯 Kotlin 逻辑；
3. 世界地图多帧确认后输出 `SpatialObject`，语音中的类别、方向和距离全部取自这个对象；
4. 空间页只保留一个危险播报入口；YOLO 回调继续更新短时语义记忆，但不独立拼接距离或触发空间危险语音；
5. 没有可靠语义绑定时可以播报“物体表面”，不得拿别的空间点为某个类别补距离。

## 数据契约

```text
Detection + 同帧 DepthSample
    -> CameraObjectObservation
       classId / label / confidence
       cameraPoint / depthSupport / depthSpread / frameId / capturedAt
    -> Anchor 变换
    -> WorldSample(object metadata)
    -> 至少两个不同深度帧、同标签、同 20 cm 空间格确认
    -> SpatialObject
       relative / distance / direction / freshness / fusion quality
```

三维对象是语音和问答的唯一“类别 + 距离”来源。普通深度表面只负责无类别危险和通行栅格。

## 告警规则

- 深度近场表面仍决定是否需要停下；
- 在近场表面附近存在已确认 `SpatialObject` 时，播报该对象自身的方向和水平距离；
- 没有空间邻近的已确认对象时，播报“物体表面”；
- YOLO 单独识别到物体但没有可靠深度绑定时，只进入画面描述和短时记忆，不生成带距离危险句子；
- 冷却、绕行和恢复前进继续由同一个空间快照入口控制。

## 自动化验收

1. 旋转 0/90/180/270 度时，检测框能够选择正确的深度采样；
2. 框内少于 5 个有效点时不生成三维对象；
3. 前后景深度跨度过大时拒绝绑定；
4. 两个检测框同时出现时，各自只取得框内的深度和类别；
5. 世界地图需要至少两个不同帧才能确认语义对象；
6. 查询某个不存在的类别时不能用其他对象替代；
7. 危险选择器只能使用与近场表面空间相邻的语义对象；
8. 原有地图、导航、语音和风险测试全部通过；
9. debug/release 单元测试及 debug APK 构建成功。

## 真机验收

1. 在近处椅子、较远门框同时入镜时，椅子的名称与距离不能使用门框距离；
2. 只有类别、没有可靠深度时不虚构距离；
3. 同一目标连续扫描后可从“物体表面”升级为具体类别，但不重复抢断播报；
4. 左右移动和转向后，对象方向随 ARCore 位姿正确变化；
5. 原有停下、左右绕行和恢复前进闭环保持可用。

## 本轮不做

- 跨会话对象追踪和家庭持久地图；
- 物体三维包围盒或实例分割；
- 扩充 COCO 之外的门、墙、台阶类别；
- 将单个语义点当成物体完整轮廓或安全净宽。
