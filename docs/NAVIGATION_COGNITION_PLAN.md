# 导航认知层实施方案（替代 RTAB-Map 路线）

> 编写日期：2026-10-02
> 状态：设计文档，待实施
> 前置依据：`CAPTURE_HEALTH_REPORT.md`（数据体检）、`HOME_MODEL_LIBRARY_PLAN.md`（模型库文件结构）
> 取代对象：`RTABMAP_MIGRATION_PLAN.md`（已删除，相关程序与产物已清理 806 MB）

## 1. 方向确认：为什么不再追 RTAB-Map

体检结论（同一批 253 帧数据）：

| 模型 | 顶点数 | X 跨度 | 覆盖体积 |
|---|---|---|---|
| 原始扫描（ARCore 位姿 + 深度融合） | 28,768 | **7.87 m** | 约 68.8 m³ |
| RTAB-Map 优化结果 | 110,744 | 3.66 m | 约 43.2 m³ |

RTAB-Map 覆盖只有原始扫描的约六成。原因是它的 RGB-D 里程计拿不到 ARCore 位姿，自行估计失败后大量丢帧（253 帧中至少 18 帧被明确 `ignored`），地图碎成 19 个子图。

**因此：基础几何模型由手机直接产出（ARCore 位姿 + Raw Depth 融合），电脑端不再做三维重建，只做认知加工。**

## 2. 分工边界

| 层 | 负责方 | 时延要求 | 说明 |
|---|---|---|---|
| 近身急停 | **手机本地** | P95 ≤ 200 ms | 独立于任何网络与后端，永远最高优先级 |
| 彩色表面（查看） | 手机 + 电脑 | 15 秒内出首版 | 家人用，不参与安全判断 |
| **导航认知层** | **电脑** | 增量 3 秒内 | 本文档的实施对象 |
| 路线与跨会话定位 | 电脑 | P95 ≤ 350 ms | 认知层达标后再做 |

**任何算法补全都不得进入安全判断层。** 急停、碰撞、路径规划只读认知模型与实时深度，不读彩色外观。

## 3. 输入

来自手机 RGB-D 关键帧流（沿用现有 VA3D 二进制协议，每帧含）：

- Raw Depth（毫米）与逐像素置信度；
- 相机内参 `fx/fy/cx/cy`；
- ARCore `cameraToWorld`（列主序 4×4，**已验证与端侧解码一致**）；
- 时间戳与 session/frame ID。

预处理规则（沿用已验证口径）：置信度 ≥ 180/255；深度 0.25–6 m；关键帧门限 3 cm / 2.5° / 0.20 s。

## 4. 认知层四层结构

### 4.1 占据证据层（Voxel Occupancy）

- 体素边长 **8 cm**，稀疏哈希存储，只保留观测过的体素；
- 每体素维护 log-odds 分数，范围 **[-12, +12]**，带时间戳；
- 更新规则：
  - 深度端点所在体素及其上半格：**+3**（占据证据）；
  - 相机到端点之间的射线（体素 DDA 遍历）：**−2**（自由证据）；
  - 同一 Raw Depth 时间戳只融合一次；
- **未知即未知**：从未被射线穿过的体素不产生任何分数，也不输出任何可走结论；
- 判读：分数 ≥ +3 判可靠障碍；≤ −2 判可靠自由；介于两者之间为暂定；正负证据都出现过且未收敛为冲突。
- 输出：`cognition/occupancy.vamap`（紧凑二进制，体素键 + 分数 + 时间戳 + 观测次数）。

### 4.2 可站立表面层

从占据层与深度表面提取，判据全部可测：

| 判据 | 阈值 | 说明 |
|---|---|---|
| 表面法向与重力方向夹角 | ≤ 20° | 超过视为墙或陡坡 |
| 局部高度连续性 | 邻域高差 ≤ 5 cm | 超过视为落差或台阶 |
| 最小可站立宽度 | ≥ 0.45 m | 窄于此不可单人通行 |
| 头部净空 | ≥ 1.90 m | 从站立面向上检查占据层 |
| 坡度 | ≤ 15° | 超出标记为坡面，不并入平地导航图 |

**楼梯与落差必须单独建模**，不得投影成单层 2.5D 地图（本阶段只识别与标注，不生成逐级引导）。

### 4.3 可通行图（Navigation Graph）

- 节点：可站立表面上、间距 ≤ 0.2 m 的采样点；
- 边：两节点间净空与支撑均达标才连边；
- 边属性：宽度、最小净空、最近障碍距离、地面类型（平地/坡面/上行台阶/下行台阶/落差）、置信度；
- **只允许在可靠自由体素与可靠可站立面上生成节点与边**；暂定、冲突、未知区域一律不生成，也不得穿越。

### 4.4 覆盖率与补扫报告

后端在每次处理后输出（这是"能不能宣称建图完成"的唯一依据）：

- 已观测体素比例 / 目标区域比例；
- 可靠支撑面覆盖率；
- 1.9 m 净空覆盖率；
- 暂定、冲突、未知体素数量与**具体位置**；
- 门洞是否经多视角确认；
- 从起点回到起点的累计闭合误差（用 ARCore 位姿直接计算）。

**覆盖率或关键通道未达门槛时，状态必须是 `NEEDS_RESCAN` 并列出补扫位置，不得显示"建图完成"。**

## 5. 状态机与红线

沿用 `HOME_MODEL_LIBRARY_PLAN.md`：`SCANNING → UPLOADED → PROCESSING → READY / NEEDS_RESCAN / FAILED`。

文案红线（与既有文档一致）：

- 绿色只称"**候选可走区域**"，禁止"安全""可以放心走"；
- 未知必须保持未知，禁止用 RGB 猜测未观测区域为可走；
- 认知层结论不得覆盖手机本地急停；
- 房间名称只接受用户口述并二次确认，视觉模型不得自动命名。

## 6. 需要清理的历史命名（实施第一步）

RTAB-Map 删除后，以下内容**功能上与 RTAB-Map 无关，只是名字带 rtab**，需要改名以免误导：

| 现在 | 改为 | 说明 |
|---|---|---|
| `tools/color_3d/rtab_dataset.py` | `rgbd_dataset.py` | RGB-D 关键帧录制器，输出标准 TUM/RGB-D 格式 |
| `tools/color_3d/validate_rtab_dataset.py` | `validate_rgbd_dataset.py` | 数据集完整性校验 |
| `models/<id>/rtab_dataset/` | `models/<id>/rgbd_dataset/` | 已采集数据目录，需迁移而非丢弃 |
| `tools/color_3d/server.py` | 保留 | 需移除对已删除 `rtab_pipeline` 的调用 |

`rtabmap/`、`rtabmap_v2/`、`rtabmap_v3/` 产物与 `RTABMAP_MIGRATION_PLAN.md` 已删除；`rtabmap-0.23.8` 程序包已删除。

## 7. 实施顺序

| 阶段 | 内容 | 完成判据 |
|---|---|---|
| S0 | 完成第 6 节改名与 `server.py` 清理 | 后端能启动、能接收并落盘 RGB-D 帧，无 rtab 字样 |
| S1 | 占据证据层（8 cm 体素 + log-odds + 未知保留） | 单元测试：无地面不出 FREE；重复深度不重复融合；自由观测能降低旧占据 |
| S2 | 可站立表面层 | 单元测试：法向/宽度/净空阈值生效；台阶与落差被单独标记 |

| S5 | 真机验收 | 走完一轮家庭路线，报告中的覆盖率与实测一致 |

## 8. 验收条件

### 自动化

1. 没有可靠地面时不产生任何 `FREE`；
2. 旧深度、重复深度、乱序包不重复写图；
3. 新的自由观测能降低旧占据证据；
4. 未知与冲突体素不参与可通行图；
5. 门洞净宽不足时不生成走廊，充足时生成；
6. 覆盖率未达门槛时状态为 `NEEDS_RESCAN`；
7. 既有 Android 端测试与 APK 构建继续通过。

### 真机

1. 一次连续家庭路线扫描后，报告中的覆盖率与实际一致；
2. 红色障碍与灰色未知在手机预览中可区分，且有文字说明；
3. 系统列出的补扫位置确实对应未确认区域；
4. 连续运行 20 分钟内存不持续增长。

## 9. 本文档未决定的事项

- 净空与宽度的最终阈值需用真机门洞实测校准，当前值为设计初值；
- 楼梯逐级引导的开放时点取决于专项验收，不在本阶段；
- 跨会话重定位与地点标注依赖认知层稳定后另行设计；
- 覆盖率门槛的具体百分比需在首轮真机数据上确定，不能凭默认值宣布达标。
